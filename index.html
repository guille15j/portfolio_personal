CASE // 01
01
TFG · Nota 10/10

FocusBot: un robot para mantener rutinas de foco y descanso

Resultado: sistema completo, desde el hardware hasta el backend, evaluado con la nota máxima.

C++ESP32React NativePythonFlaskPostgreSQLSupabaseMQTTOAuthNGINXDockerVercel
＋
El problema

La digitalización del entorno laboral y académico ha multiplicado las distracciones y notificaciones. Gestionar el tiempo desde el propio teléfono reduce la concentración sostenida.

Lo que lo complicaba

La solución debía sacar la gestión del tiempo fuera del teléfono mediante un sistema IoT completo sincronizado en tiempo real.

Qué hice

Ecosistema de tres capas:
• Dispositivo físico: robot con pantalla, táctil y audio.
• Backend: Flask + PostgreSQL sobre MQTT.
• App móvil: React Native para configuración.

Resultado

Sistema IoT funcional end-to-end con monitorización Pomodoro completa. Evaluado con 10/10.

02
Proyecto de clase · Nota 10/10

Gestión de Incidencias: sistema de tickets para soporte técnico

Resultado: el ciclo completo de un ticket con una API REST propia sólida.

JavaScriptJavaSpring BootMySQLJPAREST API
＋
El problema

Un equipo de soporte sin sistema propio que registraba incidencias manualmente sin trazabilidad.

Lo que lo complicaba

Múltiples roles (empleados, clientes) con permisos estrictos validados obligatoriamente en backend.

Qué hice

Dashboard en frontend respaldado por API REST en Spring Boot (Controller, Service, DAO, DTO) sobre MySQL con JPA/Hibernate.

Resultado

Calificación 10/10. Lógica de negocio blindada en servidor y API totalmente desacoplada.

CASE // 05
05
En producción · Competición

Comunicación serial para embarcación de competición

Resultado: señal estable toda la competición, cero pérdidas de paquetes.

CDockerRS-232ESP32
＋
El problema

Necesidad de enviar telemetría confiable entre la embarcación y la estación base durante la regata.

Lo que lo complicaba

Recursos limitados en microcontrolador y alto ruido electromagnético en el canal RS-232.

Qué hice

Protocolo serial en C con manejo robusto de errores y reconexión automática en contenedores Docker.

Resultado

Transmisión ininterrumpida sin pérdida de señal durante toda la prueba.
